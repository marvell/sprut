# Domain docs

Single context: `GLOSSARY.md` and `docs/adr/` at the repo root.

- **Before exploring**, read `GLOSSARY.md` and every ADR that touches the area you're about to work in.
- **Name domain concepts with glossary terms** in issue titles, proposals, hypotheses and test names, never with the synonyms it lists under _Avoid_. A concept the glossary lacks is either invented language (reconsider) or a real gap (note it for `/domain-modeling`).
